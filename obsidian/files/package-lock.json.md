# `package-lock.json`

**Module:** [[project-root]] · **Language:** JSON (npm-generated)

## Purpose

Pins the exact version and integrity hash of every npm package in the tree.
Machine-written — but **documented rather than excluded**, because it also
records the install-script approval the build depends on.

## Key items

### Exact versions
Records the full resolved tree (~52 packages) with `resolved` URLs and
`integrity` hashes, so `npm ci` reproduces the environment byte for byte.

Notable pins observed during development: `vite` 6.4.3, `esbuild` 0.25.12,
`svelte` 5.x, `typescript` 5.x.

### The esbuild approval
The counterpart to the `allowScripts` block in [[package.json]]. npm blocks
package install scripts in this environment; `esbuild`'s `postinstall` fetches
the platform-specific binary, and **Vite cannot bundle without it**.

Symptom when missing: `npm install` reports
`npm warn allow-scripts 1 package has install scripts not yet covered`,
then `vite build` fails. Fix:

```powershell
npm approve-scripts esbuild
npm rebuild esbuild
```

## Inputs / outputs / side effects

Read and written by npm. Determines what `npm ci` installs.

## Dependencies

**Generated from:** [[package.json]]
**Consumed by:** npm; indirectly by [[vite.config.ts]] at build time

## Notable logic / gotchas

- **Do not hand-edit.** Change [[package.json]] and re-run npm.
- **`npm ci` requires this file** and fails without it — the preferred command
  for reproducible installs.
- Committed deliberately: this is an application, not a library, so pinned
  transitive versions are wanted.
- The npm equivalent of [[Cargo.lock]] — both are generated, both are kept, and
  both encode a decision that would otherwise be lost.
