# `.gitattributes`

**Module:** [[project-root]] · **Language:** gitattributes

## Purpose

Tells git how to treat file contents — here, purely line-ending normalisation.

## Contents

```gitattributes
# Auto detect text files and perform LF normalization
* text=auto
```

## Key items

### `* text=auto`
Git inspects each file and, if it decides the file is text, stores it in the
repository with **LF** line endings while checking it out with the platform's
native convention. Files detected as binary are left untouched.

On Windows this means source files are committed with LF even though the
working tree may use CRLF — the standard arrangement for a cross-platform
repository, and the default `git init` template on Windows.

## Inputs / outputs / side effects

None at build or runtime. Consumed only by git, during checkout and staging.

## Dependencies

**Related to:** [[.gitignore]] — the two together define this project's git
hygiene
**Consumed by:** git

## Notable logic / gotchas

- **It affects binary assets by detection, not by rule.** The generated files
  in [[icons]] are detected as binary and left alone. If git ever misdetected
  one, normalisation would corrupt it — the usual fix is an explicit
  `*.png binary` rule, not needed so far. [[icon.svg]], the hand-authored
  source, is plain-text XML and needs no such rule.
- **Adding this file after commits already exist can produce a large
  renormalisation diff.** Here it was present from the initial commit, so no
  such churn occurred.
- Nothing else is configured: no `linguist-*` overrides, no merge drivers, no
  LFS.
